# Liber OCR

책장 사진 한 장에서 **책 권수**와 **책 제목**을 뽑아내는 On-Device 모델입니다.
모든 단계가 휴대폰 브라우저 안에서 실행되며, **LLM·멀티모달 대화형 모델은 쓰지 않습니다.**
쓰는 모델은 모두 이미지만 입력받는 단일 목적 비전 모델(검출·분류·초해상도·OCR)이고, 제목 교정은 비신경망 규칙과 n-gram입니다.

- 웹 데모: <https://skytinstone.github.io/shelf-ocr-ondevice/app.html> (Chrome 권장)
- 웹앱 코드: [`../web/app.html`](../web/app.html) · PC 노트북: [`liber_deprehensus.ipynb`](liber_deprehensus.ipynb)

---

## 1. 한눈에 보기

| 항목 | 내용 |
|---|---|
| 입력 / 출력 | 책장·책상·진열대 사진 1장 → 책 권수 + 책마다 제목 (카탈로그 확정 / 글자로 읽음 / 미인식) |
| 실행 환경 | 휴대폰 브라우저 (ONNX Runtime Web 1.20.1 + rten, WASM). 사진은 서버로 보내지 않음 |
| 버전 | **β1** = 책 검출 + 글자 단계 · **β2** = β1 + 권수 확정(ViT) + 업스케일(FSRCNN) + TrOCR 보조 인식 + 같은 책 합치기 |
| 모델 용량 (웹) | β1 **37.3MB** · β2 **60.6MB** (+ TrOCR 한국어 56.9MB / 영어 63.9MB, 필요할 때 한 언어씩) |
| 실행 엔진 | ONNX Runtime WASM 11.3MB + rten WASM 2.5MB |
| 성능 (책장 시험 세트 9장) | 제목 재현율 β1 48.7% → **β2 56.6%** (상대 +16.2%) · 권수 정확도 β1 87.9% / β2 87.5% |
| 실기기 (iPhone 15 Pro) | 사전 책장 25권 사진 1장: β1 47.8초 · β2 72.8초 |

| 단계 | 하는 일 | 모델 | β1 | β2 |
|---|---|---|:-:|:-:|
| ① 책 검출 | 회전 상자로 책등·표지 찾기 | YOLO11n-OBB (Liber OCR 본학습, 960 입력, 신뢰도 0.45) | ✅ | ✅ |
| ② 가짜 책 필터 | 마스크로 가짜 상자 거르기 | SAM 2.1 tiny | PC만 | PC만 |
| ③ 권수 확정 | book / not_book / partial / multiple 판정 → 나누기·합치기·버리기 | DeiT-Small (PC는 ViT-Large) | – | ✅ |
| ④ 업스케일 | 폭이 좁은 책등만 2~4배 | FSRCNN | – | ✅ |
| ⑤ 글자 검출 | 책 안의 글자 줄 찾기 | PP-OCRv5 mobile det (DBNet) | ✅ | ✅ |
| ⑥ 언어·방향 | 줄마다 0°·180°·90°·세로쓰기 중 고르기 | PP-OCRv5 mobile rec (한국어·영어) | ✅ | ✅ |
| ⑦ ROI 정렬 | 줄 사각형 펴기 + 여백 + CLAHE | (JS 영상 처리) | ✅ | ✅ |
| ⑧ 글자 인식 | 줄 글자 읽기 | PP-OCRv5 (β2는 애매한 제목 줄만 TrOCR로 한 번 더) | PP | PP + TrOCR |
| ⑨ 제목 확정 | 저자·출판사·판수 제외 → 단어 교정·어순 → 카탈로그 매칭 | 규칙 + 글자 5-gram KN + 자모 편집거리 | ✅ | ✅ |
| ⑩ 같은 책 합치기 | 제목이 같고 상자가 겹치거나 한 책등이 이어져 잘린 경우만 1권으로 | 규칙 | – | ✅ |

- β2의 TrOCR은 **카탈로그로 확정되지 않은 책의, PP-OCR 확신이 0.9보다 낮은 제목 줄만** 다시 읽고 두 인식기 중 확신이 높은 쪽을 씁니다.
- ② SAM 2는 PC 버전에서 효과를 확인했지만, **Edge Device 탑재 제약(메모리·처리 시간)으로 On-Device 버전에서는 제외**했습니다. 애매한 상자에만 부르는 조건부 호출 방식을 시험하고 있습니다.

## 3. 성능

### β1 · β2 비교

| 시험 세트 | 지표 | β1 | β2 | 변화 |
|---|---|--:|--:|--:|
| 책장 9장 (정답 113권) | 권수 정확도 (정확히 맞은 사진) | 87.9% (3/9) | 87.5% (3/9) | −0.4%p |
| | 제목 재현율 (정답 제목 중 맞힌 비율) | 48.7% | **56.6%** | +7.9%p (상대 +16.2%) |
| | 제목 정밀도 (읽어 낸 제목 중 맞은 비율) | 49.1% | **55.2%** | +6.1%p (상대 +12.4%) |
| | 제목 F1 | 48.9% | **55.9%** | +7.0%p (상대 +14.3%) |
| | 처리 시간 (사진 1장, PC Chrome) | 30.7초 | 41.0초 | +10.3초 |
| 1~3권 8장 (정답 12권) | 권수 정확도 (정확히 맞은 사진) | 79.2% (5/8) | 79.2% (5/8) | 같음 |
| | 제목 재현율 / 정밀도 | 83.3% / 90.9% | 83.3% / 90.9% | 같음 |

- 정답 파일: `../eval/gt.json` (책장 9장, 일부 사진은 셀 영역 ROI 지정) · `../eval/books_gt.json` (1~3권 8장)
- 제목은 정답과 글자 유사도 80% 이상이면 맞음. 예측 하나는 정답 하나에만 대응
- 측정: PC의 Chromium(아이폰 14 Pro 화면 크기)에서 배포 웹앱을 자동 실행
- 데모 카탈로그(138권)에 시험 사진 속 제목이 들어 있어 제목 수치는 실서비스보다 낙관적일 수 있습니다(도서 DB에 대부분의 책이 있다는 가정)

**어떤 사진에서 차이가 나나**: 굵은 제목이 크게 인쇄된 세계문학 책장(IMG_1548)은 두 버전 모두 잘 읽습니다(정답 22권 중 19 → 21권). 사전 26권을 **멀리서 찍어 책등 글씨가 작은** 사진(IMG_1545)에서는 β2가 좁은 책등을 업스케일해 β1이 못 읽던 책 5권을 읽어 냈습니다(위 칸 정답 14개 중 3 → 7개). 이 사진에서 업스케일만 끄면 2/14로 떨어집니다.

### 제거 실험 (무엇이 효과가 있었나)

| 구성 | 제목 재현율 | 비고 |
|---|--:|---|
| β1 | 46.7% | 7장 기준 |
| β2 − ④ 업스케일 | 37.8% | 7장 기준 |
| β2, 방향을 책 단위로 한 번만 결정 | 46.7% | 7장 기준 |
| **β2 (방향은 줄마다)** | **56.7%** | 7장 기준 |
| β2 − ⑧ TrOCR | 56.6% (시간 −4.3초) | 9장 기준 |
| ⑩ 같은 제목 전부 합치기 | 47.8% · 권수 78.7% | 9장 기준 → 겹치거나 이어진 상자만 합치도록 변경 |

- β2 향상의 대부분은 **④ 업스케일(FSRCNN)**에서 나옵니다.
- 이 시험 세트에서는 TrOCR이 수치를 바꾸지 못했습니다. 그래도 β2에는 켜 두었습니다.
- 같은 제목을 모두 1권으로 합치면 같은 책이 여러 권 꽂힌 책장(세계문학 22권 → 13권)에서 진짜 책까지 합쳐졌습니다.

### 검출 규칙의 효과 (직접 찍은 시험 사진 6장, 권수 오차 합)

| 검출기 | 규칙 켬 | 규칙 끔 |
|---|--:|--:|
| 본학습 검출기 (사용 중) | **10** | 11 |
| 실제 사진 미세조정 검출기 | 11 | 12 |

규칙 = 사진 가장자리 빈 배경 띠 제거, 사진 세 변 이상에 닿은 띠는 글자가 실제로 읽힐 때만 책으로 인정. 두 검출기 모두 규칙이 오차를 줄였습니다.

### 1. 본학습 — ① 책 검출기 (YOLO11n-OBB)

| 항목 | 값 |
|---|---|
| 데이터 출처 | Roboflow Universe 책등 프로젝트 4개 (CC BY 4.0) · Open Images V7 책 사진 (권수 구간별 최대 4,500장) · 이전 프로젝트 합성·실사 약 2,660장 · 1~3권 장면 보강 (책장 사진에서 오린 1~3권, 최대 3,000장 × 2회) |
| 학습 사진 | 에폭당 약 **19,300장** (604배치 × 32, 반복·증강 포함) |
| 검증 사진 | **827장 · 책 8,949권** |
| 설정 | 입력 960 · 배치 32 · 150에폭 · patience 20 · 회전 ±30° · 좌우 반전 · mosaic (마지막 15에폭 끔) |
| 학습 | **150에폭 끝까지** (조기 종료 없음) · **319분(약 5.3시간)** |
| 최종 검증 | **P 0.931 · R 0.927 · mAP50 0.945 · mAP50-95 0.802** |
| 권수 구간별 권수 정확도 (검증 세트) | 1권 82.7% · 2권 63.2% · 3권 71.4% · 4~9권 54.7% · 10권 이상 48.4% |
| 웹 신뢰도 기준 | 0.45 (Colab에서 0.15~0.60을 훑어 권수 구간별 정확도가 가장 높은 값) |
| 웹 모델 | `e_unified.onnx` FP32 11.0MB (PyTorch `det_obb_best.pt` 5.6MB) |

### 2-b. 실제 사진 미세조정 (채택 안 함)

| 항목 | 값 |
|---|---|
| 라벨 | 직접 찍은 사진 **21장**을 Roboflow(`liber-books`)에서 라벨링 — SAM 3 자동 라벨로 초안 → 사람이 검토·수정 |
| 나눔 | 학습 15장 (× 20회 반복) · 시험 6장 (IMG_1530 · 1545 · 1587 · 1591 · 1592 · 1593) |
| 추가 학습 데이터 | 실제 사진 조각으로 만든 합성 1,500장 · 책 없는 배경 200장 |
| 설정 | 본학습 가중치에서 시작 · SGD lr0 0.002 · 30에폭 · patience 10 · 입력 960 |
| 공개 검증 세트 | mAP50 0.945 → 0.937 (개선 없음) |
| 실제 시험 6장 (웹 규칙 포함) | 권수 오차 합 10 → **11** · 처리 시간 97.1초 → **100.6초**(+3.6%) · 인식 호출 683 → 704회 |
| 결론 | **감지 성능과 처리 시간이 오히려 나빠져 반려** → 본학습 검출기 유지 |

원인: 실제 사진 라벨이 15장뿐이라 양이 부족했고, 학습 후 사진 가장자리의 배경 띠를 책으로 잡는 경우가 새로 생겼습니다. SAM 3는 **라벨링 보조 도구로만** 썼고 Liber OCR 추론에는 들어가지 않습니다.

### 2-a. 합성 사진 미세조정 (채택 안 함)

합성 4,000장 + 확인용 300장 + 책 없는 배경 2,500장, 30에폭. 실제 사진에서 권수가 틀린 사진이 2장에서 4장으로 늘어 채택하지 않았습니다.
배경으로 넣은 건물 사진 때문에 건물 그림이 있는 표지를 책이 아니라고 배운 것으로 추정합니다.

| iPad Pro 11인치 (4세대) | 85.2초 | 132.6초 | 25권 · 21 → 23권 |

- 모든 기기에서 **동일한 샘플 사진(IMG_1545, 사전 책장 25권)**으로 측정했습니다. 세 기기 모두 메모리 부족 없이 β1 → β2를 끝까지 실행했습니다.
- 같은 코드·같은 사진인데도 처리 시간이 기기에 따라 최대 약 2.5배 차이 났고, β1 제목 수도 iPad Pro에서만 1권 많았습니다. **Edge Device의 아키텍처(프로세서·브라우저 이미지 처리)에 따라 성능이 다르게 나올 수 있음**을 확인했습니다. 정확한 원인은 추가 확인이 필요하며, 배포 전 기기별 검증이 필요합니다.
- 휴대폰 메모리를 아끼려고 β2 모델은 필요한 단계 직전에 불러오고, 끝나면 바로 반납합니다. 메모리가 부족해 β2 모델을 못 불러오면 실패하지 않고 그 단계만 건너뜁니다.
- 아이폰 브라우저(Safari·Chrome 모두 WebKit)는 탭 메모리 한도가 작습니다. 데모 전에는 탭을 새로 여는 것을 권장합니다.

## 8. 한계와 향후 과제

**한계**: 가장 큰 병목은 검출입니다. 못 찾은 책은 제목도 못 읽습니다(평대 사진 9권 중 4권만 검출, 흰 책등 미검출). 시험 세트가 17장으로 작아 1~2장 차이에도 수치가 크게 움직이고, 휴대폰 처리 시간(β2 55~133초)도 목표(10초 이하)보다 깁니다.

| # | 과제 | 내용 |
|---|---|---|
| 1 | 실시간 인식 (바코드 스캔 방식) | 사진을 올리지 않고 카메라를 비추면 바로 인식 — 몇 프레임마다 검출, 그 사이는 상자 추적, 가장 선명한 프레임으로 확정 |
| 2 | 1~3권 감지 성능 향상 | 2권 사진 권수 정확도 63.2%(최저) → 책상 위 몇 권 · 세운 책 · 평평한 표지 사진을 더 모아 학습 |
| 3 | 네이티브 앱 + 하드웨어 가속 | 같은 ONNX를 CoreML·NNAPI로 실행하고 검출기도 INT8로 → 처리 시간 10초 이하 |
| 4 | 도서 DB · ISBN 연동 | 도서 DB를 기기 안 경량 색인으로, 바코드가 보이면 우선 확정 → 정밀도 상승 |
| 5 | 사용자 수정 피드백 학습 | 동의한 경우만 책 조각·고친 제목을 모아 재학습(Active Learning) → 실제 데이터 부족 해결 |
| 6 | 책등 전용 한국어 OCR | 세로쓰기·장식 글꼴·좁은 책등 글씨 합성으로 인식기 미세조정 |
| 7 | 서재 등록 → 추천·전자책 연결 | 인식한 책장을 취향 신호로 추천에 반영, 다음 권·같은 저자 전자책 제안 |
